# dev 管理器设计(Windows 专属)

日期:2026-09-08
状态:**已实现并人工验收通过**(2026-09-08,窗口 + 托盘双形态;退出入口改为 `.vbs`,`.cmd` 退役)

## 背景与问题

在 Windows 上跑 `pnpm dev` 后直接关闭终端,子进程树(pnpm → cmd → node)不会随之终止——Windows 没有孤儿回收机制,node 层忽略控制台关闭信号。结果:claudex 后端(5179)、主站 vite(5173)、文件站 vite(5174)变成无主残留,下次 `pnpm dev` 端口冲突(server EADDRINUSE / vite 静默换端口)。

目标:一个 Windows 专属的「dev 管理器」——双击启动,有可见界面,可一键启动/停止 dev,停止时可靠地杀整棵进程树;窗口可收起为系统托盘常驻图标,通过托盘右键菜单控制。

## 已确认的需求决定(用户拍板)

| 问题 | 决定 |
|---|---|
| 使用平台 | 仅 Windows(不必跨平台,允许 Windows 专属能力) |
| 「缩到状态栏」含义 | 系统托盘(右下角图标区),不是任务栏最小化 |
| 形态 | 双击后出现可见窗口;窗口关闭/最小化 → 缩到托盘;托盘右键菜单同功能 |
| dev 输出 | 丢弃,不保留日志;出问题时用户手动开终端跑 `pnpm dev` 看日志 |
| 启动方式 | 手动双击入口,不做开机自启 |
| 入口位置 | d:\claudex 内(根目录放入口,主体在 scripts/ 子目录) |
| 菜单操作 | 启动 / 停止(杀进程树)/ 重启 / 打开两个站点 / 退出;退出 = 先停 dev 再退出 |
| 项目来源 | 项目从 GitHub 修改而来,Mac 为另一份副本;此工具不随同步上 Mac(git 上无用) |

## 技术路线

PowerShell 5.1 + .NET Framework WinForms(Windows 11 自带,零依赖、免编译)。
PowerShell 原生支持:WinForms 窗口、NotifyIcon、ContextMenuStrip、Timer、System.Drawing 绘图、进程管理与 `taskkill`。
单一 `.ps1` 承载全部逻辑,源码可读可改。

不使用 pm2(dev 模式行为别扭、多一个常驻 daemon)、不编译 C# exe(需 dotnet SDK)。

## 文件布局

```
d:\claudex\
├── 启动dev管理器.vbs       ← 双击入口(推荐,唯一在用):隐藏启动,零黑窗、无 cmd 窗口
├── 启动dev管理器.cmd.bak   ← 已退役:双击会留 cmd 黑窗,插掉黑窗会把管理器弄成半死残留
└── scripts\dev-manager\
    └── dev-manager.ps1    ← 全部逻辑(窗口 + 托盘 + 启停 + 状态轮询)
```

- `.vbs` 入口:`WScript.Shell.Run(..., 0, False)` 隐藏窗口启动 powershell;脚本内容纯 ASCII,无编码坑;双击无黑窗、无驻留的 cmd。**为什么弃用 `.cmd`**:powershell 共享 cmd 的 console,插掉 cmd 黑窗 = 给管理器发关闭信号 → 管理器窗口消失但进程半死残留(验收实测踩中)。
- `.ps1` 含中文 UI 文案,**必须以 UTF-8 with BOM 保存**(PowerShell 5.1 对无 BOM 的 UTF-8 中文一律乱码)——实现时实测验证。
- 入口放根目录便于双击;不加入 Mac 同步(git 上无用,中文文件名跨平台也易惹麻烦)。

## UI 设计

### 主窗口(启动即显示)

标题「claudex dev 管理器」;关闭按钮(✕)= 缩到托盘,不是退出(首次缩托盘时弹气泡提示「已最小化到托盘,右键图标操作」)。

```
claudex dev 管理器                                  ─ □ ✕

状态:● 运行中(绿)/ ○ 已停止(灰)      [每 2 秒自动探测刷新]
后端 5179: ✓  主站 5173: ✓  文件站 5174: ✓

[▶ 启动 dev] [■ 停止 dev] [⟳ 重启] [打开主站] [打开文件站] [缩到托盘] [退出]
```

- 状态判定依据:**端口实际监听**(Get-NetTCPConnection),不信任"我们自己启动的子进程"——残留进程也会如实显示为运行中。
- 三个端口独立 ✓/✗ 显示,后端 5179 为核心(它起不来则 vite 门户 200 但功能全废)。

### 托盘

- 图标:运行时用 System.Drawing 绘制(16×16 圆点:C 型字母或圆点),绿 = 有端口在跑,灰 = 全部停止;Tooltip 显示状态文本。
- 左键双击 = 唤回主窗口。
- 右键菜单:
  ```
  启动 dev
  停止 dev
  重启 dev
  ─────
  打开主站 (http://localhost:5173)
  打开文件站 (http://localhost:5174)
  ─────
  退出
  ```

## 启停与杀树逻辑(核心)

### 启动

```powershell
Start-Process -FilePath $env:ComSpec -ArgumentList '/c', 'pnpm dev > NUL 2>&1' `
  -WorkingDirectory 'd:\claudex' -WindowStyle Hidden -PassThru
```

- 树根是 `cmd.exe`(等 pnpm 结束才退出),输出在 cmd 层重定向到 NUL(按用户决定丢弃)。
- 记录根进程 PID,存为 `$script:rootPid`。
- 启动动作前检查:若任一端口已在监听 → 弹确认「端口已被占用(可能是终端里另起的 dev 或残留),仍要启动吗?」。

### 停止(杀整棵树)

1. 若记录 PID 还在 → `taskkill /PID $rootPid /T /F`(递归带走 cmd → pnpm → node 全链)。
2. 若记录丢失/已死但端口仍被占(别处起的残留)→ 兜底:按端口反查持有者 `Get-NetTCPConnection -LocalPort 5173,5174,5179` → `taskkill /PID <每个> /T /F`。
3. 立即刷新状态。

### 重启

停止(上述全逻辑)成功、端口全部释放后,自动执行启动。

### 退出语义

「退出」时若检测到端口在跑 → 弹确认「将同时停止 dev 并退出」;确认 → 走停止逻辑 → 退出进程。绝不留下孤儿。若 dev 未在跑,直接退出。

### 状态轮询

WinForms Timer,2000ms:探测三个端口 → 更新窗口状态行、圆点、托盘 Tooltip。探测开销可忽略(本机端口查询)。

## 错误处理

- **启动后 5 秒探测**:三个端口一个都没起来 → 托盘气泡 + 窗口提示「启动失败:请手动在终端运行 `pnpm dev` 查看报错」(诊断引导回手动终端,与"不保留日志"的决定一致)。若部分起来(如 vite 起、server 崩)→ 照实显示各端口 ✓/✗,不误报。
- **双开保护**:命名 Mutex(如 `claudex-dev-manager`);第二个实例启动即提示「管理器已在运行」并退出。
- **停止时无进程可杀** → 状态已停止,静默无事。
- **误杀防护**:端口反查兜底只针对 5173/5174/5179——这是本项目的约定端口,误杀他程序风险极低;记录 PID 优先,反查兜底其次。

## 非目标(YAGNI)

- 不做日志记录/查看窗(用户明确丢弃)。
- 不做开机自启(用户选手动)。
- 不做跨平台(Windows-only);不随同步上 Mac。
- 不做进程级监控/自动拉起崩掉的 server(vite/server 崩了由用户看窗口状态后手动重启)。
- 不碰 frpc、不碰生产 5179 服务的任何逻辑(本工具只管理 `pnpm dev` 的开发实例)。

## 验证清单(手动验收)——全部实测通过(2026-09-08)

1. ✅ 双击入口 → 窗口出现,中文无乱码(BOM 验证),状态「已停止」灰。
2. ✅ 点「启动 dev」→ 状态转绿;多轮启停实测。
3. ✅ 进程树形态:cmd(树根)→ pnpm → server/双 vite(记录 PID,`taskkill /T` 一次递归杀净)。
4. ✅ 点「停止 dev」→ 整棵树消失,状态转灰(日志实锤 `KILLED` + 端口复查全空)。
5. ✅ 「重启 dev」→ 停止后自动再起(按钮曾触发 5 秒看门狗 NullReference,已修:sender 参数自引用)。
6. ✅ 点窗口 ✕ → 窗口消失、进程留、托盘图标在(日志 `reallyQuit=False` 拦截);首次缩托盘有气泡提示。
7. ✅ 「退出」(dev 在跑)→ 弹确认 → 点「是」→ dev 全停、管理器退出、无残留(日志完整链 + 端口复查)。
8. ✅ 残留场景:旧实例遗留树(rootPid 丢失)→ 停止走端口反查兜底,照样杀净(实测 `KILLED 28376,33288,31844`)。
9. ✅ 二次双击 → 提示已运行,不产生第二个管理器(Mutex,程序化冒烟验证)。

### 验收中发现并澄清的行为(非 bug)

- **dev 已停时点「退出」→ 直接退出、不弹框、无输出**——设计如此,曾两度被误报为「退出没杀 dev」。加了 %TEMP%\claudex-dev-manager.log 分步日志后,用真实复现证明:退出时 `running=False` → 直退分支,行为正确。
- **退出杀树两条路径都实测**:记录 PID 优先(`KILLED <rootPid>` 单条,`/T` 递归);rootPid 丢失走端口反查兜底。
- **`.cmd` 黑窗软肋(实测踩中)**:插掉 cmd 黑窗 → 管理器窗口消失但进程残留(无日志、无窗口、无法再唤回)。此即弃用 `.cmd` 换 `.vbs` 的原因;dev 树本身独立于任何窗口,插窗不影响 dev(最早「关终端 node 仍活」同因)。
